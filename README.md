# JSONyan starter

A starter for building a [JSONyan](https://jsonyan.com) application with a React frontend and a Cloudflare Worker backend.

The browser never talks to JSONyan directly. It calls the Worker's `/api/*` routes. The Worker holds the JSONyan client credentials and calls JSONyan for it. This keeps the client secret on the server, as JSONyan requires.

## How this project was made

This directory was created with Cloudflare's project generator, using its React starter:

```sh
npm create cloudflare@latest -- starter --framework=react --platform=workers
```

When asked for a variant, **TypeScript** was chosen. Git setup and deployment were skipped.

The generator produced:

| Path                        | What it is                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------- |
| `src/`                      | The React frontend (Vite)                                                                      |
| `worker/index.ts`           | The backend: a Cloudflare Worker that answers `/api/*` requests                                |
| `wrangler.jsonc`            | Worker settings: the Worker name, the entry file, and static asset serving                     |
| `vite.config.ts`            | Vite with the React plugin and `@cloudflare/vite-plugin`, which runs the Worker during dev     |
| `worker-configuration.d.ts` | Types for the Worker's `env`, generated by `npm run cf-typegen`                                |

Requests to `/api/*` go to the Worker. Every other path serves the React app, and unknown paths fall back to `index.html`, so client-side routing works.

## 1. Set up JSONyan

1. Sign in to https://jsonyan.com and create a project, or open an existing one.
2. Open the project, choose **Clients**, then **Create client**.
   - Leave **Limit available APIs** off to allow every v1 method.
   - To restrict the client, turn it on and select the methods it may call. An app that runs workflows needs `v1.startWorkflowInstance` and `v1.resumeWorkflowInstance`, plus every method its workflow actions call, such as `v1.listRows` or `v1.createRows`. A client that also sets up tables and workflows needs the methods that create them.
3. Choose **Copy .env**. **The secret is shown only once**, so paste it right away (next step).

## 2. Local development

### Files to create

**`.dev.vars`** (required). Create it in the project root, next to `wrangler.jsonc`, and paste the content from **Copy .env**:

```ini
JSONYAN_URL=...
JSONYAN_API_PATH=...
JSONYAN_TOKEN_URL=...
JSONYAN_PROJECT_ID=...
JSONYAN_CLIENT_ID=...
JSONYAN_CLIENT_SECRET=...
```

| Variable                | Value                                                |
| ----------------------- | ---------------------------------------------------- |
| `JSONYAN_URL`           | Origin of the API, for example `https://jsonyan.com` |
| `JSONYAN_API_PATH`      | Path of the API on that origin                       |
| `JSONYAN_TOKEN_URL`     | Full URL of the token endpoint                       |
| `JSONYAN_PROJECT_ID`    | The project's ID, sent as `projectId` in every call  |
| `JSONYAN_CLIENT_ID`     | The client's ID                                      |
| `JSONYAN_CLIENT_SECRET` | The client's secret                                  |

The Worker reads `.dev.vars` when you run `npm run dev`. Vite does not, so these values never reach the browser. The file is already in `.gitignore`. Never commit it, log it, or use its values in `src/`.

**`docs/`** (recommended). JSONyan's reference, for you and your coding agent. These files have no secrets and can be committed:

```sh
mkdir -p docs
curl -fL "https://jsonyan.com/docs/jsonyan.md" -o docs/jsonyan.md
curl -fL "https://jsonyan.com/api/v0/openrpc.json" -o docs/jsonyan.openrpc.json
```

`jsonyan.md` explains the concepts (projects, tables, workflows) and how to get a token. `jsonyan.openrpc.json` is the API specification: every method, its parameters and its errors. Download it again when the API changes.

### Run it

```sh
npm install
npm run cf-typegen   # adds the JSONYAN_* names from .dev.vars to the Env type
npm run dev          # http://localhost:5173
```

`npm run dev` runs the React app and the Worker together on your machine. The Worker runs in Cloudflare's own runtime (workerd), so it behaves as it will after deployment. Nothing is deployed. Saving a file in `src/` or `worker/` reloads it. Restart `npm run dev` after changing `.dev.vars`.

In `worker/index.ts`, read the values from the `env` argument: `fetch(request, env)`, then `env.JSONYAN_CLIENT_SECRET` and so on. See `docs/jsonyan.md` for how to get a token and call a method.

## 3. Deployment

You need a Cloudflare account.

1. Log in to Cloudflare:

   ```sh
   npx wrangler login
   ```

2. Optional: change `name` in `wrangler.jsonc`. It becomes the Worker's name and part of its URL (`https://<name>.<your-subdomain>.workers.dev`).

3. Check the production build locally:

   ```sh
   npm run preview
   ```

4. Deploy for the first time, uploading the JSONyan values as Worker secrets:

   ```sh
   npm run deploy -- --secrets-file .dev.vars
   ```

   This builds the app and runs `wrangler deploy`. The values in `.dev.vars` are stored encrypted on Cloudflare as secrets, not in the code. Consider creating a separate JSONyan client for production, so you can revoke it without affecting local development. If you do, put its values in a separate file and pass that file instead.

5. Later deployments keep the secrets, so run only:

   ```sh
   npm run deploy
   ```

To change secrets without redeploying the code, run `npx wrangler secret bulk .dev.vars` for all of them, or `npx wrangler secret put JSONYAN_CLIENT_SECRET` for one.

## Scripts

| Command              | What it does                                                    |
| -------------------- | --------------------------------------------------------------- |
| `npm run dev`        | Runs the frontend and the Worker locally. Deploys nothing.      |
| `npm run cf-typegen` | Regenerates `worker-configuration.d.ts` (the `Env` types)       |
| `npm run build`      | Type-checks and builds for production                           |
| `npm run preview`    | Builds, then serves the production build locally                |
| `npm run deploy`     | Builds and deploys to Cloudflare                                |
| `npm run lint`       | Runs ESLint                                                     |
